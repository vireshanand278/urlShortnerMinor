# Little Link

A local-first URL shortener with a React interface, two Express servers, and MongoDB Community Server. Link accounts, links, passwords, and click analytics stay in your local MongoDB database.

## What you need

- Node.js 20.19+ or 22.12+
- MongoDB Community Server installed and running on this computer

The configured database is `urlshortener` at `mongodb://127.0.0.1:27017/urlshortener`. Mongoose creates the database the first time the app writes data.

## First-time setup

Install the JavaScript dependencies while online:

```powershell
npm install
```

Dependencies are then available locally; running the app does not require internet access. The interface uses system fonts and makes no requests to external services.

The project `.env` file is created for this computer and ignored by Git. It contains the local MongoDB URI and a generated signing secret. Set an admin password in it before creating the admin account:

```powershell
notepad .env
```

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` to values you choose. Admin passwords must be at least 12 characters. Then create or update the admin account:

```powershell
npm run seed:admin
```

Registration in the app creates regular user accounts; it does not grant admin access.

## Run locally

Start the React development server and both local APIs:

```powershell
npm run dev
```

Open <http://127.0.0.1:5173>. The app runs on these loopback-only addresses:

- React interface: `http://127.0.0.1:5173`
- User API and short-link redirects: `http://127.0.0.1:5000`
- Admin API: `http://127.0.0.1:5001`
- MongoDB: `mongodb://127.0.0.1:27017/urlshortener`

The user and admin servers are separate Node.js processes, both connecting to the same local MongoDB database. Both APIs listen only on `127.0.0.1`, not on your network.

For a production-style local run, build the interface with `npm run build`, then run `npm run start:user` and `npm run start:admin` in separate PowerShell windows. The user server serves the built React app at <http://127.0.0.1:5000>.

## How the code fits together

The browser sends API requests to the user server on port `5000` or the admin server on port `5001`. Both servers use Mongoose to read and write the same local MongoDB database. When someone opens a short link, the user server records the visit and redirects them to the saved destination.

Start with these files:

- `client/src/App.jsx` — sign-in, link list, analytics panel, and admin screens
- `client/src/styles.css` — the hand-written styles for the interface
- `server/user-server.js` and `server/admin-server.js` — start the two backend processes
- `server/app.js` — connects API routes and handles short-link redirects
- `server/routes/` — the request handlers for accounts, links, and admin data
- `server/models/` — the MongoDB document shapes for users, links, and clicks
- `server/middleware/auth.js` — checks a user's sign-in token
- `server/scripts/seed-admin.js` — creates the admin account from `.env`

The `client/dist/` folder is generated by `npm run build`; Vite compresses its files for delivery. Make interface changes in `client/src/`, not in `client/dist/`.

## MongoDB on Windows

MongoDB Community Server must be running before starting either API. To check:

```powershell
Get-Service MongoDB
mongosh "mongodb://127.0.0.1:27017" --quiet --eval "db.adminCommand({ ping: 1 })"
```

If the service is installed but stopped, start it from an elevated PowerShell:

```powershell
Start-Service MongoDB
```

## Features

- Email and password registration/sign-in with bcrypt password hashing
- Short links with safe HTTP(S)-only URL validation and redirects
- Per-link click totals, seven-day click chart, and recent referrers
- Admin overview of accounts, links, and clicks, plus a user directory
- Admin-only endpoints protected by role checks
- Data stored locally in MongoDB; no Atlas, third-party APIs, or runtime font/CDN requests
